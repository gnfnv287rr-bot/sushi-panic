# 后续版本路线图

当前 v0.2.0 / 2026-10-19。以下为建议顺序，不是已完成事项或未经确认的上线时间表。

## v0.1.0 — 本次交付

完整可玩生存循环、4 角色与 8 食物、约束随机、难度上限、离线单文件、原创程序美术、鼠标/触控/键盘、自动暂停和本机纪录。22 项规则测试、15 项浏览器测试、1800 局模拟，详见报告。

## v0.1.1 — 已交付：数值仪表可读性

应用用户反馈：放大数字、加粗生命与饱腹条、按状态切换颜色、增加局内危险提醒；22 项规则与 16 项浏览器回归通过。规则与平衡沿用原版。

## v0.1.2 — 已交付：提前预警

按用户反馈，在饱腹低于 25 / 超过 85、尚未进入伤害区时显示琥珀色提醒，越过危险线后升级红色。规则未改。

## 下一次修订 — 真人与真机验证后的修复

- 执行首轮 5–8 人、每人至少 3 局的观察性试玩，区分新手与熟练玩家；记录首次正确进食、角色忌口记忆、死因理解、误触与重玩选择。
- iOS Safari 与 Android Chrome 真机，至少覆盖小屏、常见屏、低性能设备，检查地址栏、安全区、横竖屏、音频恢复和持续帧率。
- 依据具体问题调整盘签、手指遮挡、提示和普通数值，保留已有核心定位与可复现种子。
- 完成条件：已知阻断问题修复，测试回归通过，观察数据与玩家原话进入项目记录；未达成前不宣称好玩或平衡完成。

## v0.2.0 — 已交付：自填 ID 与共享积分榜

按用户确认使用积分排名：玩家自行输入 ID、服务端验证个人单局最佳、榜首获得大胃王，跨访客共享。已部署 Sites Worker/D1，并更新 GitHub Pages 前端。中国原网络可达、跨设备账号恢复、专业防作弊仍未完成。

## 后续玩法候选 — 经主策划确认后，增强重复游玩

候选：同角色/同种子挑战、角色分开记录、阶段目标、轻量局内事件、练习模式或限时模式。选择其中少量做独立实验，不一次叠加。任何改变全轨点击、生存目标、随机角色或供给保底的方案，先记录具体建议、预期效果与风险，等待确认。

完成条件：相对当前版本 的实测问题有改善，且新手理解与失败公平感没有恶化。没有既有留存基线时不虚构“提升 X%”目标。

## v0.3.0 — 内容与工程扩展

在核心体验通过后扩充角色与寿司、完善声音/动作/美术、加存档迁移与资源管理。视内容规模再决定是否迁移 Phaser，或仅把渲染层换成 PixiJS。保留规则引擎与模拟器契约，避免整体重写。

## 产品化 — 独立立项

静态站正式发布、PWA/原生容器、可访问性、隐私与数据采集、可信排行榜、账号、商业化和发行平台验收，按实际发布计划分别批准。静态网页已于 2026-10-19 发布至 Sites，支持公开链接分享；共享娱乐积分榜已在 v0.2.0 实现；支付、广告和完整账号仍未实现，也未承诺商业表现。


## 当前优先事项

1. 中国朋友原网络复测页面 + 联网计分 + 结算上榜。如果 Sites API 同样受限，评估独立 API 和数据迁移；需要实际可用托管账号/域名，不能用静态镜像冒充完全解决。
2. 首批真实玩家反馈 ID、联网/练习提示与大胃王竞争动机；补真机测试。
3. 服务运行观测、数据保留/删除、跨设备找回与反滥用。仍保留无密码试玩，是否扩展正式账号由产品需求决定。


## 最新 V1.0 RC 路线（取代上述未完成版本编号计划）

已实现并本地测试：每日榜、历史存档、右下角UI、游客身份与自愿邮箱接口、Edge重放安全层。第一优先是完成Supabase账号连接、免费项目/迁移/函数/公开配置，然后验证两个真实云端玩家同步并切换正式Pages。此前仅独立练习预览可验收UI。

随后执行真机和中国朋友原网络测试，配置可用SMTP并由Owner指定收件人验收邮箱恢复，再观察额度/暂停/性能。新增角色、局内事件、角色分榜和模式变化仍需主策划确认，不因迁移而更改原规则。
