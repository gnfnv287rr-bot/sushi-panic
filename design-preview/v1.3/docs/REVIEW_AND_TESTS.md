# 三轮自检与实际测试

## 轮次一：治愈感与场景主次

实际查看1440、390、320首轮截图。奶油/薄雾绿与原寿司插画能形成温和背景，食品保留鲜色。问题：主厨背后多了一块像卡片的背景，姓名标签贴近轨道，素材看起来被分装。修改：去掉主厨额外圆角底，收掉独立姓名牌，保留一张完整木台；围裙换成原创米粒记号，避免抽象笔画像写错的汉字。

证据：screenshots/round1-1440.png、round1-390.png、round1-320.png。

## 轮次二：去模板、统一形状

第二轮对照初稿，普通导航按钮仍有网页感。修改成细绳悬挂的小菜单牌，图标全部来自同套原创SVG，保留44px目标；主动作/休息/收藏分用柔绿、天空蓝、蜜桃色。餐盘名放大，取消额外背景块而不继续堆装饰。手机压缩招牌/欢迎区和上沿状态，留更多空间给轨道。

证据：screenshots/round2-1440.png、round2-390.png；最终desktop.png/mobile.png。

## 轮次三：实际游玩和命中安全

真实浏览器操作发现：全局button:active位移覆盖餐盘居中transform，按下后餐盘会跳位，导致点击重试。修复为保留居中再轻缩放；餐盘容器pointer-events:none，实际餐盘pointer-events:auto。没有使用force点击绕过问题。

320px初次发现卡也曾与弯角餐盘的矩形点击区域接触。缩小手机新品卡、隐藏重复辅助句、将位置放回轨道空心中心；320px额外收窄至100px，取消顶端装饰星。检查一整圈100个相位×8个盘子后，卡片不与盘子的完整点击矩形重叠。卡片本身pointer-events:none。

另修正测试中茶后数值的错误假设：演示焦糖三文鱼单口增加9，喝茶减18，测试改按点击前值核验茶的变化，没有为迎合测试改正式菜品。

## 最终通过结果

- **12项预览专用Chrome自动化测试通过**，2026-10-19；不是生产端到端验收。
- 320×640、390×844、768×1024、1440×1100、844×390：无页面横向溢出，6个导航/8个餐盘/操作按钮均≥44px；未观察JS异常。
- 320/390/1440：首次发现28→29、重复不加种数、5/28本期进度、茶反馈、菜单切换、原四角色切换与忌口、阿太110精神数值、手帐、Escape关闭/焦点回到入口、存档/排行榜诚实的未接入提示、重新体验均通过。
- 轨道有运动；主动休息与减少动态效果均停轨。20秒无操作进入休息，积分与收藏不自动增加；后台切换不补算动作。
- 实际移动中的餐盘接受原生鼠标点击；没有仅用测试注入函数冒充点击。
- 服务器对/api/identity、正式index/config、Supabase配置和.env请求返回403；Demo浏览期间无外部域名/生产API请求，localStorage/sessionStorage均未写入。
- 最终独立浏览器复看：桌面1440×1000、390×844手机/触摸模拟，无JS异常、新字体真实加载；台面上沿分别在y=341/y=437。
- 本机Chrome仅一次99帧RAF样本：平均60.0fps、P95帧间隔16.7ms。它是当前电脑、当前场景的短样本，不代表低端手机、长时间游戏、GPU或电量表现。

运行日志/tests/results.json为本地生成产物，复测命令见README；可提交的摘要为tests/acceptance.json。完整正式游戏测试、跨账号/邮箱、线上上传均没有在本阶段重复执行或宣称通过。
